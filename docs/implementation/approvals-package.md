# التفويض والتوازي

الترحيل003 يضيف تفويض الخدمة المؤقت مع صاحب الصلاحية والبديل والدور والإدارة والفترة والسبب. يلزم بديل مستقل نشط في الدور والإدارة نفسيهما. التفويض لا ينتقل عبر سلسلة بدلاء، ولا يسمح باعتماد الطلب الذاتي. يعود الخادم لصلاحية صاحب الخطوة وعلاقته الحالية بصاحب الطلب في كل قراءة وقرار وتنزيل.

انتهاء الفترة أو إلغاء التفويض يسحبان وصول البديل إلى الطلب والملف والبحث. يبقى القرار المحسوم ثابتًا، ويسجل approver_id لصاحب الصلاحية وdecided_by للفاعل وdelegation_id. لا تمحو الإزالة التاريخ. التفويض خاص بمحرك الطلبات الداخلية؛ لا يوسع تلقائيًا تصاريح المالية والتوظيف أو مراجعات الاستوديو.

سياسة الخدمة تقبل mode=parallel مع خطوات مختلفة؛ كلها تحتاج قرارًا إيجابيًا قبل اعتماد الطلب. السياسة السابقة تبقى متسلسلة. الرفض أو الإعادة يغلقان الجولة، وإعادة التقديم تنشئ جولة جديدة وتحفظ القرارات السابقة. منع التكرار والنسخة الحالية يمنعان قبول قرار قديم أو إنشاء حدث اعتماد ثانٍ.

التصعيد الزمني وحدود القيمة والتفويض عبر الهيكل الإداري المؤرخ غير منفذة. هذه تغطية جزئية لـPLT-04 وIT-02 وليست اكتمال محرك الموافقات المؤسسي.

## إصلاحات ربط مثبتة

SEC-06: كانت استجابة تحميل نموذج قديم تستبدل النموذج الحالي، وكان نجاح حفظ سابق يغلق نموذجًا أحدث. أصبح لكل فتح جيل، ويتحقق التحميل والحفظ منه قبل تغيير النموذج. هدف النموذج محفوظ في WeakMap ولا يؤخذ من سجل عالمي تغير أثناء الطلب.

SEC-07: كان الخادم يفحص الجلسة قبل اكتمال جسم الطلب فقط. اختبار تأخير الجسم وسحب الدور أثبت إنشاء خدمة بصلاحية قديمة. يعاد الآن فحص الجلسة وCSRF والدور بعد اكتمال الجسم وقبل المعاملة مباشرة. اختُبر سحب الدور وتعطيل الحساب وحذف الجلسة، وفشلت الكتابة في الحالات الثلاث.

الاختبارات في approvals.test.mjs وdialog-races.test.mjs وauthorization-race.test.mjs، مع رحلات HTTP في operations-http.test.mjs.

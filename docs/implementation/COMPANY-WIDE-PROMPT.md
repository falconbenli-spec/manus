# برومبت تجهيز منصة 3,6T لجميع موظفي الشركة

> هذا البرومبت مرجع تنفيذ كامل لأي مطوّر أو وكيل ذكاء اصطناعي يستكمل المنصة. نُفذت منه في 15 سبتمبر 2026 طبقة كتالوج الخدمات، والأجزاء المتبقية موضحة في القسم 9. اقرأه كاملًا قبل التعديل.

## 1. الدور والهدف

أنت مهندس برمجيات أول تستكمل منصة التشغيل الداخلية لشركة 3,6T (وكالة تسويق واتصال وإنتاج). الهدف أن تصبح المنصة **نقطة الدخول الوحيدة لكل موظف**: يطلب منها خدماته من أي إدارة، ويتابع طلباته، ويعتمد ما يخصه، ويرى مهامه ومشاريعه، دون بريد أو ملفات إكسل أو رسائل جانبية.

النجاح يعني:
1. كل موظف يدخل بحساب الشركة ويجد إدارته وخدماته.
2. كل إدارة لها خدمات مهيأة بنموذج واضح، ومسار اعتماد صحيح، ومنفذ مسؤول، وإغلاق بدليل.
3. لا يرى أحد معاملة لا تخصه، ولا يعتمد أحد طلبه بنفسه، ولا يُتجاوز مستوى اعتماد.
4. كل قرار مسجل في تدقيق غير قابل للتعديل.
5. المنصة مستضافة ومراقبة ولها نسخ احتياطي مجرب قبل دخول أول موظف حقيقي.

## 2. السياق التقني الحالي (لا تعِد بناءه)

- **التقنية:** Node.js 24 بدون اعتماديات خارجية، SQLite عبر `node:sqlite`، واجهة JavaScript مباشرة بدون مرحلة بناء، عربية RTL بثيمين.
- **التشغيل:** `npm start` على `http://127.0.0.1:3600`، وقاعدة البيانات يحددها `LOCAL_DB_PATH` (الافتراضي `work/local.sqlite`).
- **النواة القائمة:**
  - `app/workflow.mjs`: محرك الطلبات. الخدمة = حقول + سياسة اعتماد + دور المنفذ، بنسخ ثابتة. حالات الطلب: مسودة ← معلق ← معتمد ← قيد التنفيذ ← مكتمل، أو معاد أو مرفوض أو ملغى.
  - `app/delegations.mjs`: تفويض مؤقت محدد بالخدمة والمدة.
  - `app/auth.mjs`: جلسات وCSRF وحد لمحاولات الدخول.
  - `app/db.mjs`: ترحيلات مرقمة ببصمة، وتدقيق متسلسل بالتجزئة.
  - وحدات تشغيلية: `leave` و`people` و`commercial` و`procurement` و`studio` و`finance` و`budgets`.
- **ملفات المتابعة:** `STATUS.md` و`PLAN.md` و`docs/implementation/REQUIREMENTS.json` (220 متطلبًا في 22 مجالًا) و`docs/traceability.json` (نسخة مطابقة).

## 3. قواعد غير قابلة للتفاوض

1. **البيانات مصطنعة** حتى قرار ترحيل معتمد. لا تنسخ بيانات موظفين أو عملاء حقيقيين إلى المنصة أو الاختبارات أو الأدلة.
2. **لا تعدل ترحيلًا مطبقًا ولا `app/schema.sql`.** أضف ملفًا مرقمًا جديدًا في `app/migrations/`، وأضف اختبار ترقية من قاعدة قديمة.
3. **لا تعدل ملف اختبار مسجلة نتيجته** في سجل التتبع. أضف ملف اختبار جديدًا، وإلا يفشل `npm run check`.
4. **الصلاحية تُفحص على الخادم لكل قراءة وفعل وتنزيل.** إخفاء الزر في الواجهة لا يُعد صلاحية.
5. **يُمنع الاعتماد الذاتي، وتخطي الخطوات، وتعديل نسخة مقدمة.**
6. **لا اتصال خارجي فعلي** (بريد، بنك، حكومة، منصات إعلانية) دون موافقة صريحة وموصل معتمد. أي حدث خارجي يُسجل في `outbox` بحالة محجوبة.
7. **لا تنشر ولا تدفع إلى GitHub** دون طلب صريح من صاحب المشروع.
8. **لا تقرأ أو تنسخ** `.env` أو `outputs/local-credentials.txt` أو أي سر.
9. **خذ نسخة احتياطية قبل أي تعديل على قاعدة فيها بيانات**: `node scripts/backup.mjs <المصدر> <وجهة جديدة>` ثم `restore-check`.
10. **لا تصف متطلبًا بأنه مكتمل** إلا بتحقق كل معايير قبوله وتوثيق الدليل. قبول مالك الإجراء قرار بشري لا يُسجل آليًا.

## 5. نموذج الخدمة الموحد

كل خدمة تُعرَّف هكذا (المصدر: `app/service-catalog.mjs`):

```js
{ code:'ADM-TRAVEL', req:['ADM-04'], department_id:'admin-affairs',
  name_ar:'سفر وانتداب', name_en:'Business travel', description:'…',
  fields:[ /* 1 إلى 12 حقلًا: text | textarea | date | select | number */ ],
  approval_policy:{ steps:['manager','department_manager'], handler_role:'manager' } }
```

**خطوات الاعتماد المتاحة:**

| الخطوة | من يعتمد |
|---|---|
| `manager` | المدير المباشر لصاحب الطلب، ومن نفس إدارته |
| `department_manager` | مدير الإدارة المنفذة للخدمة *(أضيفت في هذه الجلسة)* |
| `hr` | مسؤول خدمات الموظف في إدارة الخدمة |
| `it` | مسؤول الدعم التقني في إدارة الخدمة |
| `pm` | مدير مشروع في إدارة الخدمة |

- **حدود السياسة:** 1 إلى 3 خطوات، بدور مختلف في كل خطوة، بنمط متسلسل (الافتراضي) أو متوازٍ.
- **المنفذ** (`handler_role`) يستلم الطلب بعد الاعتماد، ويغلقه بملاحظة إنجاز لا تقل عن 3 أحرف.
- **حقل `number`** *(أُضيف في هذه الجلسة)*: رقم موجب بخانتين عشريتين كحد أقصى. يُرفض السالب والصيغة العلمية والنص.

**قواعد اختيار المسار:**

| نوع الخدمة | مسار الاعتماد |
|---|---|
| تمس ميزانية أو وقت الموظف (سفر، مصروفات، تدريب، عمل إضافي) | المدير المباشر ← الإدارة المنفذة |
| سرية (تظلم، بلاغ مخالفة، بلاغ أمني) | الإدارة المنفذة مباشرة، دون المدير |
| ذاتية لا تحتاج رأي المدير (تعريف بالراتب، تحديث بيانات) | الإدارة المنفذة فقط |
| يرفعها المديرون عادة (فتح مشروع، قرار تنفيذي) | الإدارة المنفذة. مدير الإدارة لا يعتمد طلبه بنفسه |

## 8. البنية المطلوبة قبل أي موظف حقيقي

1. **الاستضافة:** خادم دائم (VM أو حاوية) داخل المملكة إن اشترطت سياسة البيانات، Node 24، HTTPS، ووكيل عكسي. الخادم حاليًا يرفض أي مضيف غير محلي عمدًا، والنشر يحتاج إعداد مضيف معتمد وملفات جلسة `Secure`.
2. **قاعدة البيانات:** SQLite تكفي لتجربة محدودة. عند التوسع يُقاس الأداء (NFR-03) ويُقرر البقاء أو الانتقال إلى PostgreSQL.
3. **النسخ والتعافي:** نسخ مجدولة خارج الخادم، واستعادة مجربة شهريًا، وأهداف RPO/RTO معتمدة (IT-08، NFR-04).
4. **المراقبة:** سجلات مركزية، تنبيه عند التوقف أو ارتفاع الأخطاء (IT-07)، وخطة استجابة للحوادث (IT-10).
5. **الأمن:** مراجعة أمنية مستقلة، فحص المرفقات من البرمجيات الضارة، سياسة احتفاظ بالبيانات (LEG-05، LEG-06).
6. **الترحيل:** خطة نقل بيانات الموظفين الحالية بتنظيف ومطابقة، وخطة رجوع (NFR-08).
7. **التبني:** دليل مستخدم، تدريب لكل إدارة، قناة دعم، ومسؤول تغيير في كل إدارة (NFR-09).

## 10. طريقة العمل لكل حزمة

1. اقرأ `STATUS.md` و`PLAN.md` والمتطلبات المستهدفة في `REQUIREMENTS.json`.
2. اكتب اختبارًا يفشل أولًا: صلاحية، ورفض، وحالة حدية.
3. نفذ بترحيل جديد عند الحاجة، ثم الخادم، ثم الواجهة.
4. شغّل `npm test` و`npm run check` واحفظ الخرج في `docs/testing/<اسم>-<تاريخ>.txt`.
5. اربط الاختبارات بالمتطلبات عبر `npm run trace -- --record-results <ملف الخرج>`. لا ترفع الحالة إلى مكتمل دون تحقق كل معايير القبول.
6. خذ نسخة احتياطية، وطبّق على قاعدة المعاينة، وافحص المسار في المتصفح على سطح المكتب والجوال.
7. حدّث `STATUS.md` بنقطة الاستكمال والقيود بصدق.

## 11. المتطلبات التي لم تغطها طبقة الكتالوج بعد

هذه متطلبات بحالة "لم يبدأ" لا تمثلها أي خدمة في الكتالوج. تحتاج الوحدات في القسم 7 أو قرارات الشركة:

- **إدارة الحسابات وتجربة العميل:** ACC-04 بوابة اعتماد العميل، ACC-07 متابعة الالتزامات
- **المشاريع والموارد:** PMO-03 الاعتماديات، PMO-07 التكلفة المتوقعة
- **التسويق الرقمي والشراء الإعلامي:** DIG-04 الإعداد والقياس، DIG-08 الرصد المجتمعي
- **العلاقات العامة والإعلام:** PR-01 قاعدة الإعلام، PR-02 الخطة الإعلامية
- **التسويق عبر المؤثرين:** INF-01 سجل المؤثر
- **الإنتاج المرئي والفعاليات:** PRO-05 جدول التصوير
- **التوظيف والأداء والتطوير:** TAL-10 الترابط لا الأتمتة العمياء
- **الرواتب والمزايا:** PAY-01 قواعد مؤرخة، PAY-05 المراجعة المزدوجة، PAY-06 التحقق المالي
- **المالية والتحصيل والرقابة:** FIN-07 السيولة والبنوك، FIN-10 قرار الإحلال
- **القانونية والخصوصية والملكية الفكرية:** LEG-06 الاحتفاظ والحقوق
- **التواصل الداخلي وتجربة الموظف:** EXP-09 التوقيع والهوية

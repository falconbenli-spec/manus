# حزمة الدورة التجارية المحلية

الدوال في `app/commercial.mjs` تعمل مع `DatabaseSync` وهوية جلسة موثقة. تعيد فحص المستخدم والدور والفريق من قاعدة البيانات. يحيط المستدعي كل كتابة بـ `transaction(db, () => ...)`؛ لا تفتح الدوال معاملة متداخلة. توصيل HTTP والجلسة وCSRF ومنع تكرار إنشاء الشبكة مسؤولية الخادم.

## عقد التوصيل

- `listCommercial(db, u)`: مصفوفة ملفات مأذونة؛ لكل ملف `id`, `status`, `version`, `allowed_actions`. توجد النسخ في `quotes` والنسخة الحالية في `current_quote`، والتأهيل في `qualifications`، والقرارات في `reviews`، والعقد في `contract`، والتسليم في `deliveries`، والتغييرات في `changes`.
- `createLead(db, u, {name, registration_number, contact, source, sector})`: إنشاء ملف العميل. المالك والكيان والإدارة من الجلسة؛ رقم السجل نص لاتيني من 3 إلى 40 حرفًا أو رقمًا أو شرطة ويُوحّد إلى أحرف كبيرة. التعارض داخل الكيان يرجع `409 duplicate_registration` دون كشف بيانات السجل الآخر. يحيط HTTP الدالة بـ `createOnce` بمفتاح المحاولة.
- `commercialAction(db, u, id, action, input)`: يعيد الملف المحدّث. `input.version` مطلوب في كل إجراء. الحقول الزائدة مرفوضة.

| action | الحقول بعد version | المنفذ والبوابة |
| --- | --- | --- |
| qualify | need, budget, currency, timing, decision_maker, service_fit | المالك؛ من lead أو qualification_rejected. ينشئ تأهيلًا ثابتًا وطلب مراجعة للمدير المباشر |
| approve_qualification / reject_qualification | note | المدير المحدد في طلب المراجعة وبعلاقة إدارة حالية؛ قرار مستقل |
| save_quote | scope, currency, valid_until, lines | المالك؛ بعد تأهيل معتمد أو لمسودة عرض أو عرض مرفوض. كل حفظ نسخة جديدة |
| submit_quote | لا شيء | المالك؛ quote_draft. يطلب مراجعة النسخة الحالية من المدير |
| approve_quote / reject_quote | note | المدير المعين؛ quote_pending |
| register_contract | agreement_evidence, customer_representative | المالك؛ quote_approved. يسجل اتفاقًا داخليًا للعرض المعتمد الساري، دون إرسال أو توقيع رسمي |
| create_project | member_ids | المدير المباشر؛ contracted. يشتق الاسم والنطاق والميزانية من السجلات الأصلية ويضيف المدير والمالك والأعضاء المحددين من فريقه المباشر |
| submit_delivery | line_index, evidence | مالك الملف أو pm عضو بالمشروع؛ project_active. يربط المخرج ببند العرض التعاقدي، والفهرس يبدأ من صفر |
| accept_delivery | delivery_id, note, acceptance_evidence, customer_representative | المدير المباشر العضو بالمشروع، مع منع قبول مخرجه الذاتي؛ قبول داخلي موثق لنسخة المخرج |
| create_change | scope, additional_price, additional_cost, extra_days, due_date, acceptance | المالك؛ project_active. ينشئ طلب تغيير ثابتًا بعملة العقد، مع أثر الهامش وطلب اعتماد مستقل |
| approve_change / reject_change | change_id, note | المدير المعين وبعلاقة الإدارة الحالية |
| start_change | change_id | المالك؛ طلب معتمد. ينشئ مهمة واحدة مسندة إليه بمعيار القبول والموعد من الطلب |

`lines` مصفوفة من 1 إلى 30 بندًا: `{description, quantity, unit_price, unit_cost, discount, tax_rate, acceptance, revisions}`. `quantity` نص عدد صحيح موجب، و`revisions` عدد صحيح من صفر إلى 20. الأموال نصوص عشرية غير سالبة مثل `"125.50"`؛ العملات المحلية المدعومة SAR وUSD وEUR فقط، ولكل منها منزلتان عشريتان. `tax_rate` نص نسبة من صفر إلى 100 بمنزلتين بحد أقصى؛ لا تفترض الحزمة معدلًا قانونيًا أو سياسة ضريبية. الخصم مبلغ لكل البند قبل الضريبة، والضريبة تقرّب لأقرب أصغر وحدة لكل بند، والنصف إلى أعلى. يحسب الخادم الإجمالي والتكلفة والهامش من البنود بواسطة BigInt، ويعيد الأموال بصيغة نصوص أصغر وحدة في الحقول ذات لاحقة `_minor`. يرفض الأرقام العائمة والأسس والفواصل والقيم السالبة والمبالغ التي تتجاوز 999999999999 وحدة صغرى للعرض.

التسلسل: `lead → qualification_pending → qualified → quote_draft → quote_pending → quote_approved → contracted → project_active`. رفض التأهيل يعطي `qualification_rejected`، ورفض العرض يعطي `quote_rejected`. لا تعديل لنسخة مقدمة أو معتمدة؛ العرض المرفوض يحتفظ بنسخته ثم يسمح بإنشاء نسخة لاحقة.

## النطاق والحدود

المالك الموظف ومديره المباشر داخل الإدارة والكيان يقرآن بيانات الملف المالية. لا توجد صلاحية شاملة للمسؤول التقني. مدير المشروع ذو دور pm وعضوية صريحة يحصل على عرض تسليم محجوب الأموال: لا تكاليف أو أسعار أو هوامش أو ميزانية تأهيل أو دليل اتفاق. أعضاء المشروع الآخرون لا يحصلون على ملف العميل تلقائيًا. تغيير الدور أو تعطيل الحساب أو تغيير الإدارة أو إزالة العضوية يسري على القراءة والفعل التالي.

هذه تغطية جزئية للمتطلبات CRM-01 وCRM-02 وCRM-06 وCRM-07 وCRM-09 وACC-01 وACC-03 وACC-06 وACC-08 وPMO-01 وPMO-02. لا كتالوج تكلفة معتمد أو حدود هامش مؤسسية أو جهة عميل موثقة عبر بوابة، ولا موارد مصفوفية أو فوترة أو تحصيل أو إقفال مشروع أو اتصال خارجي. دليل الاتفاق والقبول إفادات داخلية مصطنعة للاختبار؛ لا يعني حفظها قبولًا قانونيًا أو اعتمادًا للإنتاج. لا يحول قبول المخرج المرحلة تلقائيًا إلى قابلة للفوترة.

## التحقق

الواجهة في `app/static/commercial-ui.mjs` تصدر `commercialUI` لعارض الوحدات المشترك. تعرض النماذج كل الحقول الفعلية، وتحفظ معرف الملف ونسخته عند فتح النموذج. للعرض ثلاثة بنود منظمة، الثاني والثالث اختياريان، مع الحفاظ على البنود الإضافية إن كانت موجودة أصلًا. يظل التحقق النهائي والحساب على الخادم.

شُغّل `node --test tests/commercial.test.mjs`: نجحت 16/16، صفر فشل أو تخطي. تشمل اختبارات النجاح والسالب والتكرار وعبور النطاق وسحب الدور والعضوية والإدارة وثبات النسخ والتدقيق الذري، وعقد نموذج العرض وحجب الأموال في واجهة pm. نجح `node --check app/static/commercial-ui.mjs`. يحدّث المنسق STATUS.md وسجل التتبع وأدلة الاختبار العام؛ هذه الحزمة لا تعدّل سجل المتطلبات الأصلي. اختبار المتصفح على التطبيق الموصول لم ينفذه مالك هذه الحزمة.

بوابة طلب التغيير تخص مسار التغيير التجاري، ولا تصنف المهمة العامة خارج هذا المسار تلقائيًا على أنها داخل النطاق أو خارجه. كذلك لا تتضمن حزمة قبول المخرج إعادة المخرج أو رفضه أو دعوة مفوض عميل فعلي. تبقى هذه حدودًا أمام قبول ACC-03 وACC-06 وACC-08 كاملة.

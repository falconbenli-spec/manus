# التشغيل والترحيل والاستعادة

ابدأ من README.md. أبقِ البيانات مصطنعة؛ لا توجد قناة إصدار رسمي أو دفع أو إرسال خارجي في هذه النسخة.

## إعادة تشغيل المعاينة

أوقف عملية npm start الحالية بـCtrl+C في جلستها، ثم شغّل npm start من مجلد المشروع. افتح http://127.0.0.1:3600 وأعد تحميل المتصفح بعد تغيير الملفات. لا تشغّل setup على قاعدة مهيأة.

## الترحيلات

app/schema.sql هو الإصدار 1 المحفوظ. الإصدار 2 في app/migrations/002-integrity.sql يحمي القرار المحسوم ومعرف الخطوة ويضيف مفاتيح منع التكرار. لا تعدل ملف ترحيل مطبق: openDb يرفض البصمة المختلفة. أضف ملفًا مرقمًا جديدًا واختبارًا لترقية قاعدة قديمة ذات سجلات فعلية.

قبل ترقية النسخة المحلية، احفظ نسخة من القاعدة. أداة النسخ تفتح المصدر للقراءة ولا تطبق عليه الترحيلات. لا تختبر الرجوع بالكتابة فوق ملف مستخدم.

```sh
node scripts/backup.mjs work/local.sqlite work/backups/before-change.sqlite
node scripts/restore-check.mjs work/backups/before-change.sqlite work/restored-check.sqlite
```

يلزم اسم وجهة جديد لكل تشغيل؛ الأداتان ترفضان استبدال ملف قائم. الاستعادة تراجع سلامة SQLite وتسلسل التدقيق، وتطبق الترحيلات فقط على نسخة الاستعادة الجديدة. تقارن اختبارات npm test أيضًا نص المرفق وحالات الطلب ورفض مستخدم خارج الكيان.

لتجربة النسخة المستعادة بعد التحقق، استخدم ملفها ومنفذًا محليًا آخر:

```sh
LOCAL_DB_PATH=work/restored-check.sqlite PORT=3601 npm start
```

الأزمنة المقاسة محلية؛ ليست RTO/RPO معتمدين. حفظ ملف على الجهاز نفسه ليس استراتيجية تعافٍ مؤسسية.

## بوابة الإطلاق

لا أمر نشر في الحزمة. إعداد .github/workflows/verify.yml يشغّل check وtest ولا ينشر. لم ينفذ هذا الإعداد على GitHub؛ لا remote ولا دفع. يلزم تسجيله كفحص مطلوب ضمن حماية فرع معتمد، وتثبيت مراجعة أمن وHR/مالية وأداء وقبول مالك الإجراء قبل أي إطلاق. مراجع إعداد الأفعال التي راجعناها في 10 سبتمبر: [setup-node](https://github.com/actions/setup-node) و[checkout](https://github.com/actions/checkout).

لا تتضمن هذه الجلسة اعتماد الاستضافة أو التحويل من Lovable أو ترحيل سجلات الشركة. راجع DEC09 وDEC10 وDEC13 وDEC14.

## توسعة بيانات التجربة

في تثبيت جديد فقط: npm run setup ثم node scripts/expand-demo.mjs ثم npm start. setup ينشئ الحسابات والخدمات الأصلية؛ التوسعة تضيف أربعة حسابات مصطنعة وتقويمين ونطاق توظيف وتصاريح مالية ودليل حسابات وفترة اختبار. لا تفترض أرصدة إجازات أو رواتب مستحقة.

الترحيلات 003–009 تضيف التفويض والتجارية والمشتريات والإجازات والمالية والتوظيف والاستوديو. قاعدة الجلسة مهيأة بالفعل؛ لا تعِد setup. افتح تبويبًا محدثًا بعد إعادة تشغيل الخادم. ترفض التوسعة كيانًا يختلف عن بيئة التجربة، ولا تعيد ضبط مستخدم قديم. الحسابات الجديدة تستخدم كلمة المرور المصطنعة نفسها: deputy، pm، finance-preparer، finance-approver. المراجع المالية تظهر فقط للحسابات المصرح لها.

آخر نسخة محلية: work/backups/operations-final-20260910.sqlite، ونتيجة الاستعادة docs/testing/restore-results-operations-20260910.txt. النسخ على هذا الجهاز وحده لا تكفي لتشغيل الشركة.

## التشغيل التلقائي على جهاز مالك المشروع

نُفذ البند 0.1 من docs/implementation/TASK-0.md في 16 سبتمبر 2026.

تعمل المنصة الآن كخدمة مستخدم على macOS باسم `sa.36t.platform`: تبدأ مع كل تسجيل دخول، وتعود تلقائيًا خلال عشر ثوانٍ إن توقفت لأي سبب. القاعدة المستخدمة `work/hr-design-preview-20260914.sqlite` والمنفذ 3600 محليًا فقط.

```sh
sh ops/install-autostart.sh     # تثبيت أو إعادة تثبيت الخدمة
sh ops/uninstall-autostart.sh   # إيقاف التشغيل التلقائي دون المساس بالبيانات
launchctl print gui/$(id -u)/sa.36t.platform | head    # حالة الخدمة
launchctl kickstart -k gui/$(id -u)/sa.36t.platform    # إعادة تشغيل فوري بعد تحديث الكود
```

السجلات في `work/logs/platform.log` و`work/logs/platform.error.log`، وهي داخل `work/` المستبعد من Git ومن حزم المراجعة.

حدود هذا البند: جهاز واحد فقط، ولا تعمل المنصة إذا كان الجهاز مطفأً أو المستخدم غير مسجل دخوله، ولا تُفتح من أي جهاز آخر. الوصول من أجهزة المكتب بند مستقل (0.2) ويحتاج تشفير الاتصال أولًا. تحديث الكود لا يُطبَّق حتى تُعاد الخدمة بـ`kickstart`.


## مفتاح تشفير الحقول والتحقق بخطوتين

- عند أول حفظ لحساب بنكي لمورد أو تفعيل تحقق بخطوتين يُنشأ `work/keys/field.key` (32 بايت، صلاحية 600). يمكن تحديد مسار آخر بالمتغير `FIELD_KEY_PATH`.
- **انسخه احتياطيًا في مكان منفصل عن قاعدة البيانات.** فقدانه يعني تعذر قراءة الآيبانات المشفرة وأسرار التحقق بخطوتين؛ ويُعاد حينها ضبط التحقق لكل حساب ويُعاد جمع بيانات الحسابات البنكية بتحققها المستقل.
- من فقد جهازه ورموز استرداده: يدخل الأدمن الأول إلى واجهة إعادة الضبط (`POST /api/admin/accounts/<id>/totp-reset` بسبب مكتوب)، وتنتهي جلسات الحساب ويُسجل الحدث في سجل التدقيق.


## المساعدون الذكيون ومفتاح المزود

- المساعدون معطلون حتى يفعّلهم الأدمن الأول من شاشة «المساعدون الذكيون». مساعد السياسات ومساعد المعرفة ومسودة النموذج وفحص التسليم تعمل محليًا عند عدم وجود نموذج لغوي.
- المزود الخارجي لا يعمل لمساعد حتى يُسجل في «حوكمة المساعدين»، ويُعتمد تقييم مخاطره من شخص مستقل، ثم يُفعّل. وجود المفتاح وحده لا يكفي.
- Anthropic: يضع **المالك بنفسه** `AI_PROVIDER=anthropic` و`ANTHROPIC_API_KEY=...` و`AI_MODEL=...` في بيئة الخادم، ثم يعيد التشغيل.
- مزود متوافق مع OpenAI: يضع `AI_PROVIDER=openai-compatible` و`AI_PROVIDER_NAME=...` و`AI_BASE_URL=...` و`AI_API_KEY=...` و`AI_MODEL=...`. يلزم HTTPS، ويُسمح بـHTTP فقط لـlocalhost و`127.0.0.1` لتشغيل نموذج محلي. لا يُرسل المفتاح إلى المتصفح ولا يُحفظ في قاعدة البيانات.
- سياسة البيانات الافتراضية `AI_DATA_POLICY=synthetic_only`. لاستخدام بيانات داخلية يلزم مزود معتمد وسياسة صريحة `AI_DATA_POLICY=internal_allowed`. عند تشغيل قاعدة داخلية يضبط المالك `AI_RUNTIME_DATA_CLASS=internal`؛ عندها يرفض الخادم أي مزود مصنف للبيانات المصطنعة فقط.
- سقف التكلفة الشهري لا يعمل إلا بعد إدخال سعري الإدخال والإخراج من عقد المزود؛ المنصة لا تفترض أسعارًا.
- لم يُختبر المسار مع مزود حقيقي؛ الاختبارات تستخدم مزودًا وهميًا وموصل HTTP محليًا. لا تعد القائمة المجانية أو نجاح الموصل اعتمادًا لمزود.

## بيانات العرض التجريبية

تعمل على القواعد المصطنعة فقط وترفض غيرها، ويمكن تكرارها دون ازدواج:

```bash
LOCAL_DB_PATH=work/hr-design-preview-20260914.sqlite node scripts/seed-operations-demo.mjs
```

```bash
LOCAL_DB_PATH=work/hr-design-preview-20260914.sqlite node scripts/seed-finance-demo.mjs
```

الأول يضيف عميلًا وحملة نشطة ومحتوى وخط نطاق ودورة تقييم مسودة وطلبات حضور معلقة ومقترحات المراكز الأربعة. الثاني يضيف دليل حسابات تجريبيًا وربطًا محاسبيًا **ينتظر اعتماد شخص مالي ثانٍ** داخل المنصة.

## اللقطات المجدولة والنسخ الاحتياطي

- الخادم يفحص جدولات التقارير عند الإقلاع ثم كل ربع ساعة، وينشئ لقطة مسودة للفترة المنتهية باسم صاحب الجدولة. لا يُرسل شيء خارج المنصة.
- النسخ اليومي: `node scripts/backup.mjs` ينشئ نسخة ويستعيدها في ملف مؤقت ويفحص السلامة وسلسلتي التدقيق والفواتير. تثبيت الجدولة اليومية عبر `ops/install-backup.sh` ينتظر موافقة المالك.

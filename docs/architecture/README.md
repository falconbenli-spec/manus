# البنية وحدود التنفيذ

وحدة Node 24 واحدة تستضيف ملفات الواجهة وواجهات HTTP، مع SQLite محلية وملفات ترحيل مؤرخة بالبصمة. اختيرت هذه البنية لأن المجلد كان فارغًا ولتشغيل مسار قابل للاختبار دون نقل قواعد إنتاج أو إضافة خدمات تشغيل. ليست قرارًا نهائيًا لاستبدال بوابة Lovable أو نظام HR أو المرجع المالي.

## المكونات

| الملف | المسؤولية |
| --- | --- |
| app/server.mjs | حدود HTTP والجلسة وCSRF وقائمة الملفات العامة والمعاملة الذرية |
| app/auth.mjs | تجزئة كلمات المرور بـscrypt وجلسات منتهية وعزل الحساب المعطل |
| app/workflow.mjs | تفويض الطلب والمرفق وحالات الطلب وقرارات الاعتماد والإشعارات |
| app/projects.mjs | عضوية المشروع وإسناد المهمة وإكمالها بالدليل |
| app/idempotency.mjs | منع تكرار الإنشاء حسب المستخدم والمسار والمفتاح وبصمة المحتوى |
| app/db.mjs | فتح القاعدة والترحيلات والمعاملات وبصمات التدقيق |
| app/static | واجهة تستدعي الخادم؛ localStorage لتفضيلات اللغة والثيم والحركة فقط |

## نموذج البيانات

الكيان ← الإدارات ← المستخدمون. كل مستخدم له دور وإدارة ومعرف مدير. الخدمة لها رمز ونسخة وحقول وسياسة محفوظة؛ إضافة تعديل تنشئ نسخة جديدة. الطلب يثبت الخدمة وصاحبه، ويرتبط اختياريًا بمشروع مصرح به. كل تقديم يحفظ request_versions وخطوات approval_steps للنسخة الجديدة. المرفقات داخل القاعدة، فلا توجد نسخة عامة موازية لصلاحيتها.

المشروع يحدد الأعضاء، والمهمة تشير إلى مشروع وعضو نشط. audit_events متسلسل ببصمات مع منع التعديل والحذف. هذا يساعد كشف تلف التسلسل؛ لا يثبت أن مالك نظام التشغيل أو من يملك كتابة ملفات القاعدة لا يستطيع استبدال القاعدة كلها. backup يحفظ قاعدة المعاملات والمرفقات معًا.

التقديم والقرار وتغيير الحالة والإشعار وحدث outbox تتم في معاملة واحدة. أحداث outbox محجوبة فقط، ولا يوجد عامل إرسال. version يمنع قرارًا على حالة قديمة. مفتاح Idempotency-Key مطلوب لإنشاء الطلب والمشروع والمهمة ونسخة الخدمة؛ إعادة نفس المحاولة تعيد السجل الحالي بعد التفويض، والمحتوى المختلف مع المفتاح نفسه يرفض 409.

## التفويض

| الفاعل | الحد الحالي |
| --- | --- |
| الموظف | طلباته ومرفقاتها؛ تعديل المسودة أو المعاد وإلغاء الحالات المسموحة |
| المدير | خطوات مسندة له مع تحقق دوره الحالي وعلاقة التقرير والإدارة |
| المعتمد المتخصص | خطوة مسندة مع الدور والإدارة الحالية المطابقة للخدمة |
| المنفذ | خدمة ضمن دوره وإدارته بعد الاعتماد؛ يمنع تنفيذ طلبه الشخصي |
| مسؤول المنصة | إدارة كتالوج الخدمات؛ لا وصول شامل لمحتوى معاملات الموظفين |
| عضو المشروع | قراءة مشروع عضويته؛ إكمال المهمة المسندة إليه؛ إنشاء وإسناد من مالك المشروع |

تاريخ وجود خطوة اعتماد ليس تصريحًا دائمًا. تتحقق القراءة والبحث والتنزيل والإشعارات من التفويض الحالي. لا يوجد مسار عام لتغيير الدور أو إعداد المديرين من الواجهة بعد؛ هذه فجوة إدارة هوية موثقة، وليست خدمة مكتملة.

## ما لم تنفذه النواة

لا تفويض مؤقت أو موافقات متوازية أو تصعيد. لا صلاحية استثنائية للرواتب أو الشكاوى أو بوابات عملاء أو موردين؛ هذه الوحدات غير مبنية. لا SSO/MFA أو مخزن ملفات خارجي أو فاحص خبيث أو ضمان توافر عالي. حجم الملف 2 MiB وعشرة مرفقات للطلب؛ فحص امتداد وتوقيع وليس تعقيم محتوى شاملًا.

السياسات والهيكل المصطنع لا يحلان DEC01 وDEC05 وDEC06. كل تغيير إداري حقيقي أو استضافة أو تكامل يحتاج قرار المالك والبيئة المعتمدة.

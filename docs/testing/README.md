# أدلة التحقق

تشغّل npm test اختبارات Node المضمنة على قواعد ذاكرة وملفات مؤقتة، مع خوادم HTTP محلية وجلسات متعددة. لا تعتمد على مفاتيح تتجاوز التفويض. راجع test-results.txt للأسماء والنتائج الفعلية وcheck-results.txt للفحص الثابت.

| المجموعة | ما تثبته |
| --- | --- |
| legacy-access.test.mjs | إخفاق F09 قبل التصحيح ورفض المسارات المجهولة بعده مع حفظ القواعد المعروفة |
| platform.test.mjs | الطلب والموافقات والإعادة والنسخ والمرفقات والرفض الذاتي والعزل والمشاريع والجلسة وHTTP والاستعادة |
| security-regressions.test.mjs | سحب الدور والنطاق، منع التكرار بما فيه الطلب المتزامن، حماية القرار المحسوم |
| ui-race.test.mjs | استجابات طلبات معكوسة لا تغيّر هدف النموذج؛ القرار والرفع يرتبطان بالسجل الظاهر |
| migrations.test.mjs | ترقية قاعدة إصدار 1 ذات حسابات وخدمات دون فقدها؛ تطبيق الترحيل مرة واحدة |
| traceability.test.mjs | بقاء 220 صفًا أصليًا ورفض تحريف القبول أو وصف تغطية جزئية بأنها مكتملة |

اختبار سباق الواجهة يشغّل الكود داخل VM مع DOM محدود واستجابات مؤجلة؛ لا يحل محل اختبار المتصفح الفعلي في browser-review.md. حفظ نتائج الاختبار في السجل يثبت مطابقتها لأسماء الاختبارات وبصمات ملفاتها. أي تغيير لاحق في الكود يحتاج تشغيلًا جديدًا حتى لو لم يتغير نص الاختبار.

## أهداف التقرير

صفحة الأهداف التقنية في PDF، بعد فصل المتطلبات النظامية، تقترح P95 للشاشات المعتادة ≤3 ثوانٍ تحت حمل يُحدد بعد معرفة المستخدمين والبيانات، وRPO ساعة وRTO أربع ساعات قابلين للتعديل حسب الأثر. هذه أهداف مقترحة وليست SLA معتمدًا. الاختبارات الحالية صغيرة ومحلية؛ لم ينفذ اختبار حمل ممثل لذروة الرواتب أو الفعاليات، ولم تقس خسارة بيانات مع عطل بيئة مستقلة. تبقى NFR-03 وNFR-04 غير مقبولتين بالكامل.

## حدود الفحص

npm run check يفحص صياغة وحدات JavaScript، وسلامة JSON والتتبع، وبصمات المصادر، وأنماطًا محدودة من أخطاء المصدر. لا يوجد TypeScript typecheck أو ESLint/Prettier أو تجميع تطبيق React لهذه النواة؛ لم ندّع تشغيلها. كود Lovable القديم لم يُبنَ كاملًا، واختبار GitHub Actions لم ينفذ بعيدًا. لا اختبار اختراق أو قبول مالي أو قبول أعمال في هذه الجلسة.

لحفظ تشغيل جديد دون إفساد دليل سابق أثناء الاختبار، وجّه الخرج إلى ملف جديد في work ثم انقله إلى docs/testing بعد انتهاء الأمر بنجاح، وشغّل npm run trace -- --record-results docs/testing/test-results.txt ثم npm run check. لا تغيّر حالات التحقق الكامل أو قبول المالك تلقائيًا.

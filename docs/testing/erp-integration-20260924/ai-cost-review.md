# حفظ تكلفة استجابة المساعد المحجوبة

## النطاق

الملفان المعدلان: `app/ai.mjs` و`tests/ai-governance-runtime.test.mjs`. لا ترحيل ولا تغيير صلاحيات ولا اتصال بمزود حقيقي. البيانات وقاعدة الذاكرة مصطنعة.

## السبب والإصلاح

كان فحص حالة الجرد بعد انتظار المزود يرمي خطأ داخل المعاملة قبل كتابة سجل التشغيل؛ لذا تضيع الرموز والتكلفة رغم استهلاكها. صار فحص الجرد يحفظ تشغيلًا مرفوضًا يتضمن الاستخدام الفعلي والتكلفة والسبب العام للحجب، مع مصادر فارغة وعدم ربط العميل وعدم حفظ إجابة المزود. ثم يرمي `ai_not_available` بعد إتمام المعاملة. يظل فحص عدم النشاط قبل استدعاء المزود كما هو. لا يُنفذ `prepared.record` ولا ينشأ سؤال سياسة عندما يحجب الجرد النتيجة. سجل التدقيق يحمل `blocked_by_inventory`.

## التحقق

- الأحمر `ai-cost-red.log`: 3 نجاح، فشل واحد متوقع؛ لا سجل استخدام بعد تعليق الأصل أثناء انتظار الاستجابة.
- اختبار تسعير ثابت: 10 رموز إدخال بسعر 100000 ريال للمليون و5 إخراج بسعر 200000 تعطي 200 وحدة صغرى. أرقام مصطنعة لا تمثل أسعار مزود. يؤكد الاختبار دخولها في مجموع الشهر ومنع الاستدعاء التالي عند تجاوز سقف 100 وحدة صغرى.
- نفس سيناريو الحجب يغطي `brief_gaps` و`skills_path`؛ الثاني يختبر فرع تسجيل سؤال السياسة.
- فشل وسيط في إعداد الاختبار: إعادة التفعيل عبر SQL رفضها محرس الجرد؛ صُحح الاختبار ليستعمل `activateAsset` الرسمي دون تخفيف المحرس. الدليل `ai-cost-fixture-failure.log`.
- الجولة الخضراء: 12 اختبارًا ناجحًا، صفر فشل أو تخطٍ، في `ai-cost-green.log` على Node 24.14.0؛ تضم runtime والمساعدين وحوكمة المنصة. نجح فحص الصياغة للملف و`git diff --check`.

## الحدود

التكلفة تُحسب من الاستخدام الذي يعيده المزود والأسعار المهيأة؛ غياب التسعير لا ينتج تكلفة مخمّنة. هذا الإصلاح لا يستعيد بيانات خرجت للمزود قبل الإيقاف، ولا يضيف حجزًا متزامنًا للسقف الشهري. لا تغيير في طريقة احتساب رد المزود الفارغ أو فشل الاتصال القائمة سابقًا.
